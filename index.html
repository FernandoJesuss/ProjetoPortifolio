Product Thinking

Analiso o problema antes de codar. Entrego features orientadas a métrica, não a requisito.

  • Jornada do Usuário
  • Arquitetura da Informação
  • Testes de Usabilidade

Product Thinking

Antes de qualquer linha de código, mapeio: qual é o problema real? Quem é afetado? O que muda se resolver? Essa mentalidade vem de 10 anos respondendo a incidentes em multinacional — onde a pergunta "por que isso quebrou?" sempre precedia "como consertar?".

Como aplico no dia a dia
Critério de sucesso antes da feature
Defino o que "feito" significa em métricas antes de abrir o editor — tempo de carregamento, taxa de conversão, número de cliques no fluxo.
Comunicação técnica para não-técnicos
Traduz decisões de arquitetura em impacto de negócio — sem jargão, sem overhead de contexto para quem não codou.
Questiono requisitos sem métrica
Feature sem critério mensurável é hipótese, não requisito. Funcionalidade entregue sem validação é desperdício de sprint.
Visão de usuário final em cada decisão
Cada trade-off técnico passa pelo filtro: isso vai melhorar ou piorar a experiência de quem vai usar?
Evidência real · DevBurguer

Antes de codar o painel admin, mapeei o fluxo real do operador de caixa. Resultado: reduzi de 6 para 3 o número de telas necessárias para concluir um pedido — sem perder funcionalidade. Menos código, menos bug, mais usabilidade.

Frontend Engineering

Interface não é só visual. É velocidade de carregamento, acessibilidade para todos os usuários e estrutura que um dev consegue manter 2 anos depois sem ler documentação. Performance e qualidade não são etapas — são critérios de aceite desde o início.

Como aplico no dia a dia
Core Web Vitals como critério obrigatório
LCP abaixo de 1.2s, CLS próximo de zero e FID imperceptível. Uso Lighthouse e WebPageTest como parte do fluxo, não só no final.
Componentização estratégica
Atomic design na prática — componentes reutilizáveis, testáveis e com responsabilidade única. Código que escala sem acumular dívida técnica.
SEO técnico estruturado
Schema.org, meta tags semânticas, Open Graph e estratégia de indexação. SEO como pilar de arquitetura, não ajuste de última hora.
Acessibilidade WCAG AA
Contraste, navegação por teclado, ARIA e foco visível como padrão mínimo — não como feature extra.
Evidência real · DevBurguer

Aplicação em produção com LCP abaixo de 1.2s em conexão padrão — obtido com lazy loading por rota, code splitting e otimização de assets. Fluxo de pedido completo em menos de 3 cliques no mobile.

Stack técnica
⚛️ React 🟦 TypeScript 🟨 JavaScript ES6+ Next.js CSS Modules Core Web Vitals Lighthouse SEO Técnico WCAG AA Schema.org

Backend & Architecture

APIs Node.js construídas para crescer. Autenticação, pagamentos e dados prontos para produção.

  • APIs RESTful
  • Autenticação JWT

Backend & Architecture

API boa é a que o frontend não precisa pensar — responde rápido, falha graciosamente e não expõe dados que não deveria. Construo para o cenário de escala desde o início, não como refactoring de emergência depois.

Como aplico no dia a dia
Autenticação segura por perfil
JWT com refresh token, controle de acesso por perfil (cliente/admin) e proteção contra vetores comuns — sem stack trace vazando para o cliente.
Integração de pagamentos em produção
Stripe com webhooks para confirmação assíncrona, retry automático e gestão de estados do pedido — não só o happy path.
Modelagem orientada a performance
MongoDB com índices estratégicos, aggregation pipelines para relatórios e queries que continuam rápidas quando o volume cresce.
APIs RESTful com contrato claro
Respostas padronizadas, status codes corretos e documentação que o frontend consegue consumir sem reunião de alinhamento.
Evidência real · DevBurguer

Sistema com fluxo completo em produção — pedido, pagamento via Stripe, confirmação por webhook e atualização em tempo real no painel admin. Autenticação com dois roles distintos funcionando com usuários reais.

Stack técnica
🟢 Node.js 🍃 MongoDB Mongoose JWT + Refresh Token 💳 Stripe Webhooks REST API Middlewares ☁️ AWS EC2 / S3 🐳 Docker
